## Highlights

- The desktop app and `sqz` CLI now use the same Rust archive engine for creation, browsing, testing, safe extraction, conversion, repair, export, progress, and structured errors.
- Built-in workflows cover ZIP/ZIP64, 7z, TAR and compressed TAR variants, single-stream formats, and the native `.sqz` recovery container. Optional bridges extend WIM and long-tail read support when their tools are installed.
- Split output includes PKWARE-compatible ZIP volumes, generic numbered volumes, native WIM volumes through `wimlib-imagex`, and `.sqz` volumes with optional parity sidecars. Every physical output is reported to the caller.
- SFX v1 can assemble a complete ZIP payload for Windows, Linux, or a macOS app template. The runtime lists, tests, and safely extracts its payload without automatically running archived code.
- `.sqz` supports embedded Reed-Solomon recovery, mirrored index data, bounded repair, split-volume recovery, and export to standard archive formats.
- The desktop app includes archive preview, drag and drop, reusable create and extract presets, task history, localized light and dark themes, optional system credential storage, and platform file-manager integration.
- Update checks use stable GitHub release metadata and verify package identity, checksum metadata, and the published trust state. Squallz never downloads or installs an update automatically.

## Safety and privacy

- Archive extraction rejects path traversal, Zip Slip, symlink breakout, output-limit violations, excessive entry counts, and suspicious compression ratios through shared core guardrails.
- Archive creation and conversion publish outputs transactionally, detect destination changes, and stream large files rather than loading an entire archive into memory.
- Squallz has no ads, telemetry, or file uploads. Passwords are sent to supported external tools over standard input and are stored only when the user explicitly chooses the operating system credential store.

## Known limitations

- RAR support is read-only and requires a compatible external decoder. Squallz does not create RAR archives, implement RAR recovery records, or repair damaged RAR files.
- WIM operations, long-tail unpack-only formats, and PAR2 creation depend on external tools that are not bundled. Availability is reported by `sqz doctor` and the desktop app.
- ZIP encryption protects file data but cannot hide file names. Use 7z header encryption when names must be concealed. The `.sqz` v1 container does not currently support password encryption.
- Generic `.001/.002/...` output is byte splitting, not native ZIP multi-volume output. Native ZIP sets use `.z01/.z02/.../.zip`; reading existing native sets requires a compatible `7zz` or `7z` installation.
- A self-extracting archive must be signed after its payload is assembled. The bundled template signature, if any, cannot establish trust for the final user-created artifact.
- Windows and Linux packages are published as `unsigned-preview`. Public macOS DMGs are published only after Developer ID signing, notarization, stapling, and Gatekeeper checks; verify the trust state reported for each asset.
- The Linux x64 package targets glibc 2.35 or newer.
