# Squallz 隐私说明

发布前需要随安装包和官网再次复核。

## 核心承诺

- 无广告、无捆绑、无遥测。
- 不上传压缩包内容、文件名、路径、密码、恢复数据或操作历史。
- 崩溃报告只会在后续实现 opt-in 流程后由用户主动开启；默认关闭。当前首发开发线没有启用自动崩溃上报。

## 本地保存的数据

- 设置：主题、语言、UI 模式、强调色、安全阈值、性能选项等。
- 历史记录：最近打开或最近操作的本地路径，仅用于应用内体验。
- 桌面应用更新检查缓存：最近一次成功检查的时间，以及 GitHub 已公开的版本、安装包名称、下载地址、
  大小、SHA-256 和信任状态；最多复用 24 小时，不包含本地文件信息。CLI 检查不会写入这份缓存。
- 密码：只有用户显式选择记住当前压缩包密码时，才写入系统密码库。当前后端覆盖 macOS Keychain、
  Linux Secret Service（通过 `secret-tool`）和 Windows Credential Manager；每个平台都必须用对应
  smoke 在真实目标系统验收后才能作为正式发布证据。
  Linux 会先通过 `gdbus` 只读检查当前桌面会话是否有默认密码库；这项检查不会创建、解锁或修改密码库。
  Squallz 不把明文密码写入设置、localStorage、日志或任务队列。
- 诊断报告：本地诊断输出不得包含明文密码或压缩包内容。

## 网络访问

检查更新只会通过 HTTPS 读取固定的 `yangzhg/Squallz` GitHub Releases 稳定版元数据、发布清单和
当前平台对应的公开信任证据，不会上传或下载用户文件。桌面应用默认启用自动检查，在启动时触发且
24 小时内最多联网一次；可以在“设置 / 通用”中关闭，手动“检查更新”仍由用户主动触发。

CLI 不会自动或在后台检查更新。只有用户显式运行 `sqz check-update` 时才会联网；`sqz --version`
只显示本地版本。`sqz check-update` 是只读检查，不会下载或安装更新软件包。更新请求的 User-Agent 包含
当前 Squallz 版本，GitHub 也会像其他 HTTPS 服务一样看到连接 IP 和常规网络元数据。Squallz 不发送
设备标识、文件路径、归档内容、操作历史或遥测，也不会静默下载或安装更新。`sqz update` 只修改
用户指定的本地压缩包，不是软件更新命令。

未来如果加入可选崩溃报告、帮助站链接或应用内安装，必须在发布说明和本页中继续说明触发条件、
发送内容和关闭方式。

## 外部工具

某些格式可能需要本机安装的外部工具，例如 7zz/7z、wimlib-imagex 或 par2。Squallz 只通过本机进程调用
这些工具处理用户指定的本地文件；是否随包分发这些工具取决于许可证和发布检查。

## 归档内条目打开

- 打开普通归档条目时，Squallz 会把所选文件流式写入当前进程专用的私有临时目录，再交给系统默认应用。界面只持有不透明会话 ID，不会收到临时绝对路径。
- 用默认应用打开或在 Finder 中显示时，文件会保留到当前 Squallz 进程退出，避免外部应用仍在读取时被提前删除。
- 若进程崩溃或系统断电，操作系统临时目录中可能暂时留下明文副本。下一次启动 Squallz
  时，预览工作区会在跨进程 owner 锁已经释放、版本化记录与目录内标记完全匹配、权限和文件类型
  符合约束，并且目录中只有 Squallz 允许的预览文件时，精确回收该实例遗留的工作区。仍在使用、
  记录损坏、标记不符、含符号链接或未知文件的目录都会保留，避免误删其他实例或用户数据。
- 删除临时文件不等同于对存储介质做安全擦除；文件系统快照、交换空间、备份或曾经打开该文件的
  外部应用仍可能保留副本。遇到无法由 Squallz 安全确认归属的残留时，可以使用操作系统的临时
  文件清理和磁盘管理能力进一步处理。

## 用户控制

- 可以在设置页关闭历史相关体验或清理本地记录。
- 可以在密码弹窗或密码本入口忘记某个压缩包的已保存密码。
- 可以用 CLI 的 `--json` 输出做自动化，同时避免解析面向人的文本。
